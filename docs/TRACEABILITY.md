# QueueWise Requirements Traceability Matrix

**Source:** [PRD.md](PRD.md)  
**Date:** 2026-09-17  
**Scope:** MVP functional requirements FR-001 through FR-065 and non-functional requirements NFR-001 through NFR-010.

## Status Legend

- **Implemented:** code and a corresponding test or verifiable contract exist.
- **Partial:** some of the requirement exists, but one or more acceptance elements are incomplete.
- **Planned:** the requirement is recorded in the design/test plan but its owning implementation is not present yet.

The matrix intentionally names missing API/module surfaces as `Planned`; it does not invent endpoints that are not in the repository.

## Traceability Gaps Requiring Delivery Work

1. Appointment availability/listing/cancellation and customer token detail APIs are not complete.
2. Service, counter, user, assignment, policy, closure, and notification management APIs are not present.
3. Several frontend paths are intentional placeholders: service catalog, token detail, history, counter console, admin management, and audit log browsing.
4. Analytics currently provides averages and grouped demand/counter results; median, utilization, filtering, and export remain planned.
5. PostgreSQL/Testcontainers evidence is skipped when Docker is unavailable; those tests must run in CI with Docker.
6. The final acceptance gate is not yet complete for every row marked `Partial` or `Planned`.
